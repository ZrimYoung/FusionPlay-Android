# 播放时保持亮屏

设置中新增“播放时保持亮屏”，默认开启；旧版配置缺少该字段时也按开启处理。手动关闭会保存，重启 App 后仍保留。

App 在前台且接收端播放状态为播放中时，保持屏幕亮起。暂停、停止播放、关闭开关或离开 App 后，恢复系统的正常息屏规则，不会立即关屏。重新进入 App 时会按当前播放状态重新判断。适用于妙播、AirPlay、DLNA 的统一播放状态。

此功能使用当前窗口的 `FLAG_KEEP_SCREEN_ON`，不修改系统息屏时间，也不额外申请权限；不会阻止用户主动关屏。

版本：`1.2.4-screenawake`（10213）。此前已实机验收的版本保留在 `v1.2.4-native-mode` 标签及对应 GitHub Release 中。新版本增加亮屏功能，未改变原生投屏开关或音频延迟补偿设置。

验证：覆盖旧配置默认开启、关闭选择持久化、其他设置修改后的保留，以及界面开关回调。实机已验证播放时持有亮屏标志、手机暂停后释放且进度不再变化、返回桌面后释放、重新进入播放界面后恢复。未更改系统息屏计时设置。

## 停止投送状态修复（1.2.4-stopfix / 10214）

实机发现手机停止投送后音频流已关闭，但 `media_channel_closed` 被界面状态归约器忽略，播放状态和进度仍保留，也使亮屏标志无法释放。

修复以当前 `media_generation` 为依据：音频 EOF、音频失败或明确 TEARDOWN 后立即标为暂停，停止进度；保留两秒切歌重连窗口，没有新 OPEN 时清理会话。新的媒体流会取消旧流的清理，旧流的延迟关闭和重复关闭不会影响新流。仅 RTSP 控制通道关闭不作为独立音频流结束的证据。停止后的延迟播放通知不能重新激活已关闭的流；普通暂停仍保留媒体信息。

补充修复：暂停时播放源仲裁器已释放，随后停止仍必须清理该源的缓存和前台信息，不能依赖仲裁器的“当前播放源”条件。

验证：36 项 Android 单测通过，含 5 项新回归测试；构建成功。10214 已通过用户停止投送复验，用户确认界面和进度恢复正常；随后可重新投送。手机暂停的系统播放状态为 PAUSED，亮屏标志释放，连续超过 15 秒进度不变。退后台及返回前台的窗口标志也已核对。

## 重启验收限制（2026-10-26）

目标小米盒子重启后，一次授权、亮屏设置和声音校准均保留。但是系统开机时将本应用标记为 `stopped=true`，恢复广播没有完成处理，原生投屏暂停记录仍然保留。手动打开 FusionPlay 后恢复成功，记录清空，App 开关仍可使用。本设备的自动开机恢复验收未通过，不能声称已支持无人值守重启恢复。

当前使用方法：重启前先关闭“暂停原生投屏”，或返回桌面等待原生投屏恢复，再重启。如果重启前仍处于暂停模式，重启后手动打开一次 FusionPlay 以恢复。关闭调试后的最新版本 USB 复验中，用户按要求操作开关并重新投送后反馈“似乎一切正常”；作为本轮短时使用观察通过，未验证长期稳定性。退后台/返回 App 时接收服务本轮未丢失，但此前偶发的服务退出问题仍未独立定位。

## 播放页默认焦点与桌面名称（1.2.4-tvfocus / 10215）

播放内容首次出现、直接打开已有播放内容的页面、或关闭设置回到播放页时，默认选中播放／暂停。进度和歌曲信息刷新不会抢走手动选择的焦点；设置打开期间开始投送也不会抢走设置焦点。待机时仍可直接使用设置入口。

桌面名称统一为 `FusionPlay`，安装包标识保持 `com.fusionplay.android.portfix`，覆盖安装保留已有设置。

验证：26 项相关 Flutter 遥控器／设置测试通过，静态检查通过。此版本的盒子安装与遥控器实测待完成；此前 stopfix 的实机结果不替代本次验收。
